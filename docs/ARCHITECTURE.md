# 架构与边界

## 数据流

自然语言 → Provider → Pydantic Scene → 参数确认 → 有界线程队列 → 新 Blender 进程 → GLB / OBJ / 统计 → HTTP 文件 → R3F。Provider 不依赖 bpy；查看器不负责生成替代房屋。

Scene 版本 1.0、米、Y-up、XYZ 欧拉角（度）。位置和旋转是相对父节点的局部变换。父对象必须存在，禁止循环与重复 ID。0.9 仅支持单位 `m` 到 `meters` 的显式迁移；未来版本必须提供具体迁移函数，未知版本拒绝。

Blender 几何内部 Z-up，通过 C=Rx(90°) 转换 Scene 变换，再以 glTF 的 Y-up 导出。模型组以 Scene 对象 ID 命名，使查看器能够选择并更新对象组。OBJ 同样导出 Y-up，不能保证层级或材质表达与 GLB 等价。

## 持久化与任务

SQLite 项目包含描述、Scene JSON、更新时间和最近模型 ID；Scene 和 Object 在该 JSON 中聚合保存，当前没有单独的规范化 Scene / Object 表。任务、资产、解析历史有独立表。二进制文件放在 `backend/data/<UUID>/`，数据库只存 ID 和元数据。STUDIO_DATA 可改变存放目录。

两个工作线程，最多八个排队及运行任务。每个任务使用独立工作目录、独立 Blender factory-startup 进程，最多两条 Blender 线程，120 秒超时，失败记录状态。服务重启将未完成任务标记失败，不自动重试。仅支持单后端进程运行；多 Uvicorn worker 和分布式调度未实现。

## 已实施安全措施

- 输入文本上限 4,000 字符；写请求体最多 512 KB；浏览器导入最多 50 MB。
- 最多 50 个 Scene 对象，每类规则解析最多 12 个。参数限制尺寸、楼层、开口和缩放，禁止 NaN / Infinity、未知字段、非法颜色及循环父子关系。
- 下载只接受规范 UUID 和白名单扩展名，解析后验证文件仍在数据根目录内。
- subprocess 参数数组、禁止 shell、绝不 eval/exec LLM 输出；只执行仓库内的可信建模器。
- 默认规则模式离线；远程 LLM 只在用户选择并在服务端配置后调用。Key 不进数据库，Provider 错误不回显 HTTP 凭据。
- 默认只监听 127.0.0.1；CORS 只允许两个本地开发来源。

## 尚需加强

尚无 OS 级内存 / CPU 配额、Windows Job Object 隔离、独立低权限沙箱、取消任务、进程树清理或按磁盘配额自动清理。失败日志保留在任务目录便于排查，文件与历史需要用户手动管理。文件大小限制在浏览器端，不对 GLB 解压后内存用量作保证。未认证 API 仅用于可信本机，不能当作多用户公网服务。GLTF 外部资源应谨慎使用，首版只声明支持内嵌资源。

房屋是参数化外观模型：正面真实窗洞与窗框、薄玻璃 Mesh、独立侧后墙；没有完整室内装修、楼梯、门扇开合和结构工程语义。四坡采用金字塔式简化，garage 为附属体块与车库门立面；不是完整车库内部。日式与现代风格目前共享几何实现，style 是预留参数。窗户集中正面；不支持任意开口布置。默认规则只识别常用词，无法完整理解任意自然语言、否定或空间关系，始终给出检查提醒。

家具由实际部件组成，但复杂家具参数与逼真 PBR 不在首版范围。材质使用纯色粗糙度；不支持完整材质节点编辑。导出的是最后一次建模快照；视图编辑需重建后进入新导出文件。外部 OBJ 无伴随 MTL，外部 GLTF 不提供多文件上传。

## 下一版

优先补齐完整材质导入、直接导出视图编辑、TransformControls、更多语义解析与布局、独立构件参数及测试；随后加入资源配额、取消和回收、Windows 桌面封装。专业 3D 引擎通过 Future3DProvider / 独立生成适配器接入，当前明确不提供结果。
